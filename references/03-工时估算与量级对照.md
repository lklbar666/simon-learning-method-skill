# 03 · 工时估算与量级对照

> 这是西蒙学习法相对于其他学习法最硬的一块——**它敢给数**。
> 这份文件做三件事：① 把原书两个矛盾的数据点解开 ② 给出可直接用的估算式 ③ 用书里全部案例反查，标定"短时间"到底短到什么程度。

---

## 一、原书给的两个数据点

### 数据点 A（前言）

> "一门学问所包含的信息大约可以拆分成 **5 万个组块**。学习和记忆 1 个组块大约需要 **1.5 分钟**，5 万个组块则大约需要 **7.5 万分钟**，大约是 **1250 个小时**。假设每天学习 8 个小时，大约需要 **156 天**，大约是 **5.2 个月**。"

算术核对（`[已证实]`，本次实算）：

```
50,000 × 1.5 分钟 = 75,000 分钟 = 1,250 小时  ✓
1,250 ÷ 8 = 156.25 天                        ✓
156.25 ÷ 30 = 5.21 个月                      ✓
```

**三步算术全对。** 所以问题不在算术，在参数。

### 数据点 B（4.9 节专栏，人力资源管理实战知识）

> "我们可以将人力资源管理实战知识划分成 **27 个模块，520 个组块**……以上共有 520 个组块，**每个组块的学习大约需要 15 分钟**，一共需要学习大约 **130 个小时**。"

算术核对：

```
520 × 15 分钟 = 7,800 分钟 = 130 小时  ✓
```

**这两个数据点，单组块时间差了整整 10 倍**（1.5 分钟 vs 15 分钟）。原书没有任何一处解释这个差异。

---

## 二、解开矛盾：两种性质的组块

差异不是笔误，是两个不说明就自相矛盾、说清了就完全自洽的概念：

| | 1.5 分钟组块 | 15 分钟组块 |
|---|---|---|
| 定义 | 一个**可记忆的知识点** | 一个**能实战的操作单元** |
| 完成标志 | 能复述出它是什么 | 能在实际场景里做出来 |
| 认知层级 | 编码（encoding） | 编码 + 理解 + 程序化 |
| 时间构成 | 读一遍 + 记一遍 | 读 + 想 + 做 + 改 + 再做 |
| 对应原书的词 | "学习和记忆" | "学习" |

**关键在措辞**：数据点 A 写的是"学习**和记忆**"，数据点 B 写的是"学习"。原书在 A 处自己加了"记忆"，说明它知道这里量的是"记住"；但在下结论时（"5.2 个月学会一门学问"）把"记住"当成了"学会"。

> **这个滑坡是全书最重要的一处口径错误。** 它导致所有引用"5.2 个月"的地方都在夸大方法的能力。

---

## 三、两条独立路径，同一个答案

### 路径 1：直接换算

```
"知道"一门学问 = 50,000 组块 × 1.5 分钟 = 1,250 小时
"会用"一门学问 = 50,000 组块 × 15 分钟  = 12,500 小时
```

### 路径 2：用 721 法则反推

原书 2.5 节：掌握一门技能需 **10% 学知识 + 70% 练习 + 20% 讨论**。

如果 1,250 小时只是那 10%：

```
1,250 ÷ 0.1 = 12,500 小时
```

### 结果

```
路径 1：50,000 × 15 分钟 = 12,500 小时
路径 2：1,250 ÷ 0.10     = 12,500 小时
                                        ↑ 完全一致
```

**两条口径完全不同、参数来源完全不同的路径，收敛到同一个数。** 这基本可以确认：12,500 小时是"会用一门学问"的合理量级，而 1,250 小时只是"知道"的量级。

> 这是本 skill 唯一一处我认为可以称得上"发现"的东西。它也顺带解释了为什么 721 法则即使出处有问题、结论方向仍然可用——因为它和组块模型在数学上是同一件事的两种写法。

## 四、可直接用的估算式

```
T_知道 = N × 1.5 / 60        （小时，N = 组块数）
T_会用 = T_知道 × 10          （小时，等价于 N × 15 / 60）
```

### N 怎么估

原书只给了两个锚点：**一门学问 ≈ 50,000**（前言）、**人力实战 520 / 27 模块**（4.9 节专栏）。

下面的分级表是从这两个锚点插值外推的，标 `[推测]`：

| 目标粒度 | N 量级 | T_知道 | T_会用 | 现实参照 |
|---|---|---|---|---|
| 单个操作（学一个软件功能） | 5–20 | < 1 h | 1–5 h | 看一个教程 |
| 一套工具的基础用法 | 200–500 | 5–12 h | 50–125 h | 周末加几个晚上 |
| 一门考试的单科 | 800–2,000 | 20–50 h | 200–500 h | 一个月业余 |
| 一个职业的核心实操 | 3,000–8,000 | 75–200 h | 750–2,000 h | 半年到一年全职 |
| 一门学科（本科专业级） | ~50,000 | 1,250 h | 12,500 h | 6.25 年（按 2,000 h/年） |

**这张表最有用的一行是最后一行**：它给出"短时间学会一门学问"的真实代价。**6.25 年。**

### 修正系数

三条经验修正（均为 `[推测]`，但在书内案例上验证过方向）：

| 情形 | 系数 | 依据 |
|---|---|---|
| 有现成教材/课程，结构已被别人整理过 | × 0.7 | 省掉了自己拆组块的成本（原书 4.1 节承认"章节目录本身是作者划分好的组块"） |
| 只需应付封闭范围的考试 | × 0.5 | 幂次法则砍掉一半以上（曹骏、妤妤的案例） |
| 目标是"能讲清楚"而非"能做出来" | × 0.3 | 跳过 70% 的练习段 |

三者可叠加，但**叠完低于 0.15 就要怀疑**——那已经不是学，是了解。

这一步的目的：看真实案例的工时落在哪个量级，验证上面的模型。

### 反查结论

**三处吻合（刘谦、妤妤、注会），量级对得上。** 这给了模型相当的可信度。

**两处无法验证**（邢国芹、朱新明），因为书中没给完整时间数据。

**一处值得注意**：注册会计师的 2,150 小时是全书最硬的实测数据，它对应的是"六科、封闭范围、纯应试"。用它反推单科 358 小时，落在"一门考试单科 200–500 h"区间内。**这个交叉验证独立于我的模型，说明分级表不是拍脑袋。**

## 六、"短时间"到底多短

这是全书的标题承诺，也是最需要澄清的地方。

### 关键洞察

刘谦 21 小时学会一首曲子，和"一门学问 12,500 小时"，**不矛盾**。因为：

```
刘谦的目标 = "弹这一首曲子"       → 组块化后只剩一小撮关键组块
书里的目标 = "学会一门学问"        → 全部 5 万组块
```

**所谓"短时间学会"，真正起作用的机制是"把目标粒度压到足够小"，不是"单位时间效率提高十倍"。**

这个机制在原书里被反复演示，但从未被点明：

| 案例 | 缩短工时的真实手段 | 属于幂次法则的哪一招 |
|---|---|---|
| 刘谦 | 不学识谱，直接学按键动作 | 砍掉非必要知识 + 换更直接的材料 |
| 刘谦 | 5 段中 1/3/5 相同 → 学 1 段得 3/5 | 找重复结构 |
| 邢国芹 | 用"试"替代识谱 | 换更直接的方法 |
| 曹骏 | 只做近 5 年真题 | 缩小范围 |
| 妤妤 | 先做题再听课，只重点听错题部分 | 换学习顺序，避免平均用力 |

**五个人用了同一种机制的五种变体：把范围压到极小，然后在这个极小范围内做深。**

### 反面

按正统路径走的成本：

| 目标 | 正统路径 | 工时 |
|---|---|---|
| 弹一首粤语歌 | 先学粤语语法 → 发音 → 流利对话 → 再学歌 | 原书 4.6 节：**至少 1 年** |
| 弹一首钢琴曲 | 识谱 → 乐理 → 指法 → 曲目 | 通常数年 |
| 弹《致爱丽丝》 | 直接学按键动作 | **21 小时** |

差距不是效率，是**目标定义**。正统路径的目标其实是"会弹钢琴"，而刘谦的目标是"弹这一首"。

> **给用户的直接建议**：任何"3 个月速成"的承诺，都要追问一句——它承诺的是"知道"还是"会用"？如果是"会用"，再用一次"目标粒度"检查：它是不是偷偷把"一门学问"换成了"一个具体任务"。
> 这不是骗术，**这是正确做法本身**。问题只在于承诺方不告诉你它做了这个替换。

## 七、估算式的使用流程

在实际方案里怎么用：

```
1. 先定目标粒度（S2）
   → 问："我要的是能做什么？" 把它写成一句可判定的话

2. 估 N（S3 拆完组块后可以直接数）
   → 拆出来的组块数就是 N（15 分钟口径）
   → 如果拆的是"知识点"口径，N × 10 才是实操口径的等效量

3. 算 T_会用 = N × 15 / 60
   → 乘修正系数（教材 ×0.7 / 应试 ×0.5 / 只需讲清楚 ×0.3）

4. 和 S0 的时间额度比
   → 超了：砍粒度 / 补额度 / 拉长周期，三选一

5. 砍粒度的方法：把一个 N=5,000 的目标拆成五个 N=1,000 的子目标
   → 每个子目标单独可交付，而不是等全部学完才有产出
```

### 第 5 步为什么重要

原书 4.1 节说组块化的第三个好处是"积极反馈"——**化大为小，才能在短时间获得学习成果的喜悦**。

从工时模型看，这句话有个精确的版本：

> 单个组块 15 分钟 → **每 15 分钟就有一次"学会了一个东西"的确认**。这是唯一能维持长期动机的节奏。如果目标是"学完整门学科"，反馈周期是 12,500 小时，人撑不到。

---

## 八、这个方法不擅长估算的情形

诚实列出：

1. **创造性工作**（写作、设计、研究）。组块模型假设知识是"可枚举的"，而创造性产出依赖组块之间的**新组合**，组合空间无法枚举。
2. **需要身体协调的技能**（游泳、乐器演奏的肌肉记忆）。这类技能的时间成本主要在重复次数，不在组块数。刘谦的 21 小时能成立，一部分原因是他只需要"弹出来"，不需要"弹得好"。
3. **极度依赖天赋差异的领域**。原书 2.8 节自己引了"让兔子学游泳"的寓言，说明它知道有些事不是时间问题。
4. **目标本身会变的情形**。"我学三个月看看喜不喜欢"——这类探索性学习不该套估算式，套了反而会误判失败。

一个总的原则：**估算式的用途是"判断目标是否定得过大"，不是"承诺交付时间"。** 前者是规划工具，后者是赌注。
